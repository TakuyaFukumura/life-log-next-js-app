# ライフログアプリ 要件定義書

## 1. 文書情報

| 項目 | 内容 |
| --- | --- |
| 対象システム | life-log-next-js-app |
| 文書の目的 | 場所と出来事を時系列で記録し、地図上で振り返るための要件を定義する |
| 初版 | 2026-09-05 |
| 対象範囲 | 位置情報、場所名、時期、出来事の記録・表示・入出力 |
| 対象外 | 写真の登録・表示、ユーザー認証、複数ユーザー機能 |

## 2. 背景と目的

ユーザーが訪れた場所や思い出を、場所の座標・場所名・時期・出来事とともに記録し、地図上のマーカーから確認できるライフログアプリを構築する。

開発環境ではSQLite等のDBを利用できる構成を想定するが、本番環境ではDBに接続できない場合がある。そのため、**CSVを読み込んで地図に表示する機能はDBなしで成立すること**を最優先の動作保証とする。DBはデータの永続保存や検索を補助するオプションとして扱い、CSVを正とする運用にも切り替えられる設計とする。

## 3. 想定利用者と利用シナリオ

### 3.1 想定利用者

- 個人で自分の行動履歴や思い出を管理する利用者
- CSVを編集して一括でライフログを整備したい利用者
- 地図をクリックして座標を確認しながら記録を作成したい利用者

### 3.2 主要シナリオ

1. 利用者がCSVファイルを読み込む。
2. アプリがCSVを検証し、問題のない行をライフログとして保持する。
3. 地図上に各ログをマーカー表示する。
4. マーカーを選択すると、場所名・時期・出来事・座標を確認できる。
5. 利用者が地図上をクリックし、その地点の緯度・経度を確認する。
6. 利用者が必要に応じて、選択中の座標を新しいログの入力値として利用する。
7. DBが利用可能な環境ではログをDBへ保存し、DBからの読み込みを利用できる。
8. 利用者が保持中のログをCSVとしてダウンロードする。

## 4. 機能要件

### FR-01 ライフログデータの管理

1件のライフログは、次の項目を持つ。

| 項目 | 必須 | 型・制約 | 説明 |
| --- | --- | --- | --- |
| `id` | 任意 | 文字列または整数。一意 | DB保存・更新時の識別子。CSV入力時は未指定なら生成する |
| `latitude` | 必須 | 数値、-90以上90以下 | 緯度（WGS84、度） |
| `longitude` | 必須 | 数値、-180以上180以下 | 経度（WGS84、度） |
| `place_name` | 必須 | 文字列、1文字以上 | 場所名 |
| `period` | 必須 | 文字列 | 年月日、年月、期間、または利用者が読める時期表現 |
| `event` | 必須 | 文字列、1文字以上 | 出来事・メモ |
| `created_at` | 任意 | ISO 8601日時 | 登録日時。未指定時はシステムが設定 |
| `updated_at` | 任意 | ISO 8601日時 | 更新日時。未指定時はシステムが設定 |

写真用の項目やファイル参照は初期リリースでは持たない。

### FR-02 CSV読み込み（DBなしで利用可能）

- ファイル選択UIからUTF-8のCSVを読み込める。
- ヘッダー行を必須とし、標準列名は `id,latitude,longitude,place_name,period,event` とする。
- RFC 4180相当の引用符、カンマを含む値、改行を含む引用値を扱える実装とする。
- BOM付きUTF-8は読み込めることが望ましい。
- 必須列の欠落、空の必須値、数値でない座標、座標範囲外の値を行単位で検出する。
- エラー行がある場合は行番号と理由を画面に表示し、正常行は利用可否を明示したうえで取り込めるようにする。全体を無言で破棄してはならない。
- 読み込み完了後、DB接続なしでブラウザ上の状態から地図表示まで到達できる。
- 初期リリースではCSVの自動監視やサーバー上の任意パス読み込みは行わない。

### FR-03 地図表示

- 読み込んだログを地図上のマーカーとして表示する。
- マーカー選択時に、場所名、時期、出来事、緯度、経度をポップアップまたはサイドパネルで表示する。
- ログが0件の場合は空状態を表示し、CSV読み込み操作を案内する。
- 複数ログが同一座標に存在する場合、情報が重ならず確認できる表示方法（一覧、クラスタリング等）を採用する。
- 地図タイルの帰属表示を行い、タイル取得失敗時も読み込んだログの一覧またはエラー説明を確認できるようにする。
- モバイル幅を含む画面で地図とログ詳細を利用できる。

### FR-04 地図クリックによる座標取得

- 地図上のクリックで緯度・経度を取得し、画面上で確認できる。
- 座標は少なくとも小数点以下6桁程度の精度で表示する。
- 「座標をコピー」操作を提供する。クリップボード非対応時は手動選択できるテキスト表示にする。
- 取得した座標を新規ログ入力フォームへ設定できる導線を用意する（入力フォームを初期リリースで実装しない場合も、座標確認機能は独立して成立させる）。
- クリック地点と既存ログの選択状態を混同しない。クリック地点の座標と選択中ログの詳細を区別して表示する。

### FR-05 DB保存・読み込み（利用可能な環境）

- DB利用設定が有効な場合、ライフログをDBへ登録・更新・削除できる設計とする。
- DBから取得したデータは、CSVから読み込んだデータと同じ表示モデルに変換する。
- DB接続失敗時にアプリ全体を利用不能にせず、CSVモードへ切り替えられる。
- DBへの書き込み結果と失敗理由を利用者に通知する。
- DBスキーマにはライフログの各項目、一意なID、作成日時、更新日時を持たせる。
- DBとCSVの両方から同一IDのデータを取り込む場合の優先順位や重複処理は、後述の検討事項で決定するまで明示的な自動マージを行わない。

### FR-06 CSV出力

- 現在保持しているライフログを、標準列順 `id,latitude,longitude,place_name,period,event` でCSVダウンロードできる。
- UTF-8で出力し、カンマ、改行、ダブルクォートを含む値は適切にエスケープする。
- 出力対象が0件の場合も、ヘッダーのみのCSVを出力するか、出力不可の理由を表示する（仕様決定後に統一する）。
- DBを利用している場合は、出力対象（全件、検索結果、選択中など）を明確にする。
- ブラウザのダウンロード機能で完結し、DB接続を必須にしない。

### FR-07 エラー・状態表示

- 読み込み中、読み込み成功、部分成功、入力エラー、DB利用不可、地図タイル利用不可を利用者が識別できる。
- エラーは開発者向けスタックトレースではなく、原因と対処方法を含む利用者向けメッセージで表示する。
- 重要な操作には再試行または別経路（例：DB失敗時のCSVモード）を提供する。

## 5. 非機能要件

### NFR-01 可用性・実行環境

- DBに接続できない本番環境でも、CSV選択から地図上のマーカー表示までを完了できる。
- CSVモードの主要処理はクライアント側で完結させ、サーバーAPIやDBを経由しない経路を持つ。
- Leaflet等のブラウザ依存ライブラリはSSR対象外として安全に読み込む。既存の `map-next-js-app` の構成を参考にする。

### NFR-02 データ品質

- 座標はWGS84の緯度・経度として統一する。
- CSV入力時に暗黙の単位変換や曖昧な列解釈を行わず、形式エラーを通知する。
- CSV出力後に再読み込みしても、値が欠落・変質しない（日時の表示形式など決定した正規化を除く）。

### NFR-03 セキュリティ・プライバシー

- ライフログは個人情報になり得るため、初期リリースではCSVを外部サーバーへ自動送信しない。
- CSVの値をHTMLとして解釈せず、画面にはテキストとして表示する。
- CSV出力時は、表計算ソフトでの数式解釈（CSVインジェクション）への対策方針を決定する。
- 地図サービスの利用規約、タイルの帰属、アクセス制限を遵守する。

### NFR-04 操作性・アクセシビリティ

- ファイル選択、CSV読み込み、CSV出力、座標コピー、ログ詳細確認をキーボードでも操作できる。
- ボタンには目的が分かるラベルを付け、エラーや読み込み結果をスクリーンリーダーが認識できる状態通知にする。
- 地図だけに依存せず、選択ログの座標とテキスト情報を画面上にも表示する。

### NFR-05 保守性・テスト

- CSVパーサー、バリデーション、表示用データ変換、CSV出力をUIから分離してテスト可能にする。
- DBモードとCSVモードで同じドメイン型を利用する。
- 次の自動テストを用意する：正常CSV、引用符・カンマを含むCSV、空ファイル、列不足、座標エラー、部分取り込み、CSV再出力、地図クリック座標表示、DB接続失敗時のCSV表示。

## 6. 画面要件（初期案）

### 6.1 メイン画面

- ヘッダー：アプリ名、CSV読み込み、CSV出力、DBモード状態
- 操作領域：読み込み結果、エラー行、クリック地点の座標、座標コピー
- 地図領域：地図、ライフログマーカー、マーカー詳細
- ログ一覧または詳細領域：選択ログの全項目。地図非表示時の代替確認手段とする

### 6.2 初期表示

- CSV未読み込み時は、利用手順とCSVの必須列を表示する。
- 初期中心位置とズームは設定値で管理する。初期値は参考アプリに合わせて東京周辺を候補とするが、固定値は実装時に決定する。

## 7. データ・処理方針

### 7.1 データの流れ

```text
CSVファイル ──> CSVパーサー ──> バリデーション ──> ライフログモデル ──> 地図・一覧
                                                        │
                                                        ├─> CSV出力
                                                        └─> DBアダプター（任意）
DB（利用可能時） ──> DBアダプター ──────────────────────┘
```

- UIはデータの取得元を直接意識せず、ライフログモデルを受け取って表示する。
- DBアダプターは任意依存とし、DB初期化や接続失敗がCSVモードの起動を妨げないようにする。
- ブラウザで選択したCSVの保持方法（メモリのみ、IndexedDB等）は、永続性とセキュリティの検討結果に応じて決定する。初期要件ではページ再読み込み後の保持を必須としない。

### 7.2 CSVサンプル

```csv
id,latitude,longitude,place_name,period,event
1,35.6762,139.6503,東京駅,2026-01,友人と食事をした
2,34.6937,135.5023,大阪駅,2025-12-24,出張で訪問
```

## 8. 参考実装・技術方針

- 既存の `C:\Users\user\Documents\GitHub\map-next-js-app` を地図表示の参考実装とする。
- 特に、`react-leaflet` による `MapContainer`、`TileLayer`、`Marker`、`Popup` の構成、Leafletアイコン画像の設定、ブラウザ依存コンポーネントのSSR無効化を再利用候補とする。
- 本プロジェクトのNext.js App Router、TypeScript、Tailwind CSS、既存のSQLite（`better-sqlite3`）を前提にする。ただしCSVモードはSQLiteの初期化処理から独立させる。
- 地図タイル提供元はOpenStreetMapを第一候補とするが、公開・本番利用時の利用規約、レート制限、可用性を確認して決定する。

## 9. 受け入れ基準

1. DB接続を無効にした状態で、サンプルCSVを選択すると2件のマーカーが地図に表示される。
2. マーカーを選択すると、場所名、時期、出来事、緯度、経度が確認できる。
3. 地図を任意の地点でクリックすると、クリック地点の緯度・経度が小数点以下6桁程度で確認でき、コピーできる。
4. 不正な座標を含むCSVを読み込んだ場合、該当行と理由が表示され、仕様どおり正常行を扱える。
5. DB接続できない場合でも、CSV読み込み、地図表示、CSV出力が利用できる。
6. 読み込んだデータをCSV出力し、そのCSVを再読み込みしてもログの必須項目が維持される。
7. デスクトップとモバイル相当の画面幅で、主要操作とログ詳細が利用できる。

## 11. 初期リリースの範囲外

- 写真のアップロード・保存・表示
- ユーザー登録、ログイン、共有権限
- 地名検索、逆ジオコーディング
- 複数ユーザー間の同期・共同編集
- 地図タイルの完全オフライン化
- 高度な分析（移動経路、統計、ヒートマップ）
