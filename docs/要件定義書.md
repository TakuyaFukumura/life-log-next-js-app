# ライフログアプリ 要件定義書

## 1. 文書情報

| 項目 | 内容 |
| --- | --- |
| 対象システム | life-log-next-js-app |
| 文書の目的 | 日々の出来事を記録し、後から振り返るための要件を定義する |
| 初版 | 2026-09-05 |
| 現在の対象範囲 | 出来事の登録・一覧・編集・削除、タグ管理、データ入出力 |
| 初期実装の優先範囲 | 出来事の登録・一覧・編集・削除 |

## 2. 背景と目的

思いついた時に日々の出来事を記録し、時系列で振り返れる個人向けのライフログアプリを構築する。
1日1件の日記ではなく、1日に複数件の出来事を登録できるモデルを基本とする。

## 3. 利用者と公開範囲

- 利用者は個人1名とする。
- 記録は非公開とする。
- 初期版ではユーザー登録、ログイン、複数ユーザー、共有機能を実装しない。
- 個人環境で利用するため、アプリ内の認証機能は設けない。

## 4. 機能要件

### FR-01 出来事データの管理

1件の出来事は次の項目を持つ。

| 項目 | 必須 | 型・制約 | 説明 |
| --- | --- | --- | --- |
| `id` | 必須 | 一意な文字列または整数 | DB保存・更新・入出力時の識別子 |
| `body` | 必須 | プレーンテキスト、最大1,000文字 | 出来事の本文 |
| `occurred_at` | 必須 | ISO 8601日時 | 出来事の日時。登録時刻を初期値とし、利用者が編集できる |
| `timezone` | 必須 | `Asia/Tokyo` | 日時の基準タイムゾーン |
| `tags` | 任意 | 0個以上のタグ | 既存タグの選択または新規作成が可能 |
| `created_at` | 必須 | ISO 8601日時 | 登録日時 |
| `updated_at` | 必須 | ISO 8601日時 | 最終更新日時 |
| `deleted_at` | 任意 | ISO 8601日時またはNULL | ゴミ箱へ移動した日時 |

- 写真、気分、位置情報、地図情報は初期版のデータモデルに含めない。
- 本文は空文字を許可しない。
- タグ数に上限は設けない。
- 表示・入力形式はプレーンテキストとし、Markdownやリッチテキストは扱わない。

### FR-02 出来事の登録

- 一覧画面の「記録する」ボタンから登録モーダルを開く。
- 本文を必須入力とする。
- 日時には登録時刻を初期表示し、利用者が変更できる。
- 既存タグを選択できる。
- 入力中に新しいタグを作成して付与できる。
- 入力エラーは項目ごとに利用者へ通知する。

### FR-03 出来事の一覧・振り返り

- 初期表示は新しい出来事から順に並べる。
- 件数が増えた場合はページ送りで表示する。
- タグによる絞り込みを提供する。
- 初期版では本文検索を提供しない。
- 一覧画面はスマートフォンとPCの両方で利用できるレスポンシブな構成とする。
- 記録が0件の場合は、記録作成を案内する空状態を表示する。

### FR-04 出来事の編集・削除

- 一覧の編集ボタンから、登録時と同じモーダルを開いて編集する。
- 編集時は本文、日時、タグを変更できる。
- 削除操作では記録をゴミ箱へ移動する。
- ゴミ箱へ移動する際は確認ダイアログを表示する。
- ゴミ箱へ移動した記録は通常の一覧から除外する。
- ゴミ箱画面で記録を復元できる。
- ゴミ箱画面から記録を完全削除できる。

### FR-05 タグ管理

- 既存タグの一覧を表示できる。
- タグ名を変更できる。
- タグを削除できる。
- タグ削除時は、そのタグだけを記録から外し、記録自体は残す。
- タグ名は重複させない。

### FR-06 データ保存

- データはサーバー側のSQLiteに保存する。
- 既存の `better-sqlite3` を利用する。
- UIはDB実装の詳細に直接依存せず、出来事のドメインモデルを介してデータを扱う。
- DBの読み書きに失敗した場合は、利用者に原因を通知する。
- 個人利用を前提とするため、初期版では認証・認可によるアクセス制御は行わない。

### FR-07 データのエクスポート・インポート

- 記録データをJSONまたはCSVとしてエクスポートできる。
- JSON・CSVともに本文、日時、タグ、識別子などの記録情報を欠落なく扱う。
- JSONまたはCSVをインポートできる。
- インポート時に既存データと同一と判定された記録は自動的に取り込まない。
- インポート処理の失敗は無言で無視せず、対象と理由を利用者に通知する。
- エクスポート・インポートはDBの利用を前提とするが、具体的なファイル形式と重複判定キーは実装時に確定する。

## 5. 非機能要件

### NFR-01 操作性

- 主要操作はスマートフォンとPCの双方で利用できる。
- 登録・編集はモーダルで完結し、一覧画面から操作できる。
- ボタンには目的が分かるラベルを付ける。
- 入力エラー、保存成功、保存失敗、インポート結果などを利用者が識別できる状態表示を行う。
- キーボード操作とスクリーンリーダーで主要操作を利用できるようにする。

### NFR-02 データ品質

- 本文は保存前に最大1,000文字で検証する。
- 日時は `Asia/Tokyo` を基準に保存・表示する。
- タグ名の前後空白や空文字を適切に検証する。
- 削除は論理削除を基本とし、完全削除を明示的な操作として分離する。

### NFR-03 セキュリティ・プライバシー

- 記録内容を外部サービスへ自動送信しない。
- 本文やタグをHTMLとして解釈せず、画面にはテキストとして表示する。
- エクスポートファイルは個人情報になり得るため、サーバー上に不要に保存しない。
- 認証を導入する場合は、個人利用前提を崩さない形で別途設計する。

### NFR-04 保守性・テスト

- 出来事のバリデーション、タグ操作、論理削除、インポート・エクスポートをUIから分離してテスト可能にする。
- SQLiteのデータアクセス処理をUIから分離する。
- 最低限、次の自動テストを用意する。
  - 本文の必須・最大文字数の検証
  - 日時の初期値と編集
  - タグの作成・付与・名前変更・削除
  - 記録の登録・一覧・編集・ゴミ箱移動・復元・完全削除
  - JSON・CSVのエクスポートとインポート
  - インポート時の重複除外

## 6. 画面要件

### 6.1 メイン画面

- アプリ名を表示する。
- 「記録する」ボタンを表示する。
- 新しい順の出来事一覧を表示する。
- タグによる絞り込み操作を表示する。
- ページ送りを表示する。
- 各記録に編集・削除操作を表示する。
- データのエクスポート・インポート操作へ移動できる。
- ゴミ箱画面へ移動できる。

### 6.2 登録・編集モーダル

- 本文入力欄（必須、最大1,000文字）
- 日時入力欄（登録時刻を初期値として設定）
- タグ選択欄
- 新規タグ作成操作
- 保存、キャンセル操作
- 入力エラー表示

### 6.3 タグ管理画面

- タグ一覧
- タグ名変更
- タグ削除
- タグ削除時の影響を説明する確認表示

### 6.4 ゴミ箱画面

- ゴミ箱にある記録一覧
- 記録の復元操作
- 記録の完全削除操作
- 完全削除前の確認表示

## 7. データ・処理方針

### 7.1 データの流れ

```text
登録・編集UI ──> 入力検証 ──> 出来事ドメインモデル ──> SQLite
                                      │
                                      ├─> 一覧・タグ絞り込み
                                      ├─> ゴミ箱・復元・完全削除
                                      └─> JSON/CSV入出力
```

- UIはSQLiteのテーブル構造を直接扱わない。
- 一覧取得時は論理削除済みの記録を除外する。
- ゴミ箱取得時は論理削除済みの記録だけを対象にする。
- 日時の基準は `Asia/Tokyo` に統一する。

### 7.2 初期実装の順序

1. SQLiteのスキーマと出来事のドメインモデルを定義する。
2. 出来事の登録・一覧取得・編集・論理削除を実装する。
3. 一覧画面、登録・編集モーダル、ページ送りを実装する。
4. ゴミ箱、復元、完全削除を実装する。
5. タグ管理とタグ絞り込みを実装する。
6. JSON・CSVのエクスポート・インポートを実装する。

## 8. 受け入れ基準

1. 本文を入力して出来事を登録でき、登録時刻が日時の初期値として設定される。
2. 本文が空、または1,001文字以上の場合は登録できず、理由が表示される。
3. 登録済みの出来事が新しい順に一覧表示される。
4. 一覧から本文、日時、タグを編集できる。
5. 一覧から削除した記録がゴミ箱へ移動し、復元または完全削除できる。
6. 既存タグの選択と新規タグの作成ができる。
7. タグ名を変更でき、タグ削除時も記録自体は残る。
8. タグで一覧を絞り込める。
9. 一覧がページ送りで表示される。
10. JSONまたはCSVへエクスポートでき、エクスポートしたデータをインポートできる。
11. インポート時に同一データが重複登録されない。
12. スマートフォンとPCの画面幅で主要操作を利用できる。

## 9. 初期リリースの範囲外

- 写真のアップロード・保存・表示
- 気分や体調の記録
- 位置情報、地図表示、逆ジオコーディング
- 本文検索
- ユーザー登録、ログイン、共有権限
- 複数ユーザー間の同期・共同編集
- 外部サービスへの自動バックアップ
- Markdown・リッチテキスト編集
